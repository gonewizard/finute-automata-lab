Реализация и исследование детерминированных и недетерминированных конечных автоматов: построение автоматов в системе JFLAP и их программная реализация на языке Java с использованием табличного представления.

## 2. Постановка задачи

### 2.1. Вариант 15а - ДКА

Построить детерминированный конечный автомат в алфавите `{a, b}`, допускающий все строки, длина которых не кратна 5.

**Примеры:**
- `a` (длина 1) - принадлежит языку;
- `ab` (длина 2) - принадлежит;
- `aaaa` (длина 4) - принадлежит;
- `aaaaa` (длина 5) - не принадлежит;
- `aaaaaaaaaa` (длина 10) - не принадлежит.

### 2.2. Вариант 15б - НКА

Построить недетерминированный конечный автомат, допускающий язык имён переменных языка Java. Ключевые слова игнорируются.

**Правила:**
- первый символ - буква, `_` или `$`;
- последующие символы - буквы, цифры, `_` или `$`.

**Примеры:**
- `x`, `abc`, `_temp`, `$var`, `x1` - принадлежат;
- `1abc`, `9`, `-x` - не принадлежат.

### 2.3. Требования к реализации

1. Автоматы должны быть построены в системе JFLAP.
2. Программная реализация - на языке Java.
3. Обязательно использование табличного представления автомата.
4. Использование функций обработки строк (`length()`, `charAt()`, `substring()`, `matches()` и т.п.) в логике распознавания запрещено.
5. Результат программы должен совпадать с результатом JFLAP на тех же тестовых цепочках.

## 3. Теоретическая справка

### 3.1. Детерминированный конечный автомат

ДКА - это пятёрка `M = (Q, Σ, δ, q₀, F)`, где:
- `Q` - конечное множество состояний;
- `Σ` - конечный алфавит;
- `δ: Q × Σ → Q` - функция переходов (для каждого состояния и символа ровно одно следующее состояние);
- `q₀ ∈ Q` - начальное состояние;
- `F ⊆ Q` - множество принимающих состояний.

Строка принимается, если после её прочтения автомат оказывается в одном из состояний `F`.

### 3.2. Недетерминированный конечный автомат

НКА - это пятёрка `M = (Q, Σ, δ, q₀, F)`, где:
- `δ: Q × Σ → 2^Q` - функция переходов возвращает множество возможных состояний.

Строка принимается, если существует хотя бы один путь, ведущий в принимающее состояние. НКА удобен для описания регулярных языков, но любой НКА можно преобразовать в эквивалентный ДКА.

## 4. Часть А. Детерминированный конечный автомат

### 4.1. Идея построения

Ключевое наблюдение: чтобы определить, кратна ли длина строки числу 5, достаточно отслеживать остаток от деления длины на 5. Возможных остатков - пять: `0, 1, 2, 3, 4`. Значит, автомат имеет ровно 5 состояний.

При чтении любого символа (`a` или `b`) длина увеличивается на 1, значит остаток увеличивается на 1 по модулю 5.

### 4.2. Формальное описание

```
M = (Q, Σ, δ, q₀, F)

Q = {q0, q1, q2, q3, q4}
Σ = {a, b}
q0 = q0
F = {q1, q2, q3, q4}
δ задана таблицей ниже.
```

### 4.3. Таблица переходов

| Состояние | a | b |
|-----------|---|---|
| **→ q0**  | q1 | q1 |
| **\* q1** | q2 | q2 |
| **\* q2** | q3 | q3 |
| **\* q3** | q4 | q4 |
| **\* q4** | q0 | q0 |

Обозначения: `→` - начальное состояние, `*` - принимающее.

### 4.5. Логика работы

- `q0` - остаток 0. Если строка заканчивается здесь, её длина кратна 5 → reject.
- `q1` - остаток 1 → accept.
- `q2` - остаток 2 → accept.
- `q3` - остаток 3 → accept.
- `q4` - остаток 4 → accept.

## 5. Часть Б. Недетерминированный конечный автомат

### 5.1. Идея построения

Для языка имён переменных Java нужны состояния, различающие:
- прочитан ли первый символ и является ли он допустимым;
- что было прочитано в начале - буква/`_`/`$` или цифра.

Состояния:
- `q0` - начальное, ждём первый символ;
- `q1` - первый символ был буквой/`_`/`$`, читаем остальные;
- `q1'` - дубль `q1` (для недетерминизма);
- `qerr` - ловушка: первый символ был цифрой.

### 5.2. Алфавит (группы символов)

Для удобства в JFLAP и в коде используются группы:
- `L` - любая буква (`a-z`, `A-Z`);
- `D` - любая цифра (`0-9`);
- `_` - подчёркивание;
- `$` - знак доллара.

### 5.3. Формальное описание

```
M = (Q, Σ, δ, q₀, F)

Q = {q0, q1, q1', qerr}
Σ = {L, D, _, $}
q0 = q0
F = {q1, q1'}
δ задана таблицей ниже.
```

### 5.4. Таблица переходов

| Состояние | L | D | _ | $ |
|-----------|---|---|---|---|
| → q0  | q1, q1' | qerr | q1, q1' | q1, q1' |
| q1 | q1 | q1 | q1 | q1 |
| q1'| q1' | q1' | q1' | q1' |
| qerr  | qerr | qerr | qerr | qerr |

Обозначения: `→` - начальное, `*` - принимающее.

### 5.5. Граф переходов

![img_3.png](img_3.png)

### 5.6. Логика работы

- Из `q0` по букве/`_`/`$` можно попасть одновременно в `q1` и `q1'` - это и есть недетерминизм.
- Из `q0` по цифре - только в `qerr` (ловушка, из которой выхода в принимающее состояние нет).
- `q1` и `q1'` - принимающие; из них по любому допустимому символу идём в себя.
- Строка принимается, если хотя бы один путь привёл в `q1` или `q1'`.

### 6.2. Реализация ДКА - `DfaVariant15.java`

Автомат хранится в виде:
- массива `ALPHABET` - символы алфавита;
- двумерного массива `TRANSITIONS[state][symbolIndex]` - таблица переходов;
- массива `ACCEPTING[state]` - какие состояния принимающие;
- константы `INITIAL_STATE` - начальное состояние.

Метод `run(char[] input)` проходит по массиву символов и переключает состояние по таблице. Функции обработки строк не используются.

```java
public static boolean run(char[] input) {
    int state = INITIAL_STATE;
    for (int i = 0; i < input.length; i++) {
        int idx = symbolIndex(input[i]);
        if (idx == -1) {
            System.out.println("Ошибка: символ '" + input[i] + "' не входит в алфавит {a, b}");
            return false;
        }
        state = TRANSITIONS[state][idx];
    }
    return ACCEPTING[state];
}
```

### 6.3. Реализация НКА - `NfaVariant15.java`

Автомат хранится в виде:
- массива `ALPHABET`- символы алфавита;
- трёхмерного массива `TRANSITIONS[state][symbolIndex]` - массив возможных следующих состояний (для НКА каждая ячейка содержит не одно состояние, а список);
- массива `ACCEPTING[state]`;
- константы `INITIAL_STATE`.

Эмуляция НКА использует множество текущих состояний (`Set<Integer>`). На каждом шаге для каждого текущего состояния собираются все возможные следующие.

```java
public static boolean run(char[] input) {
    Set<Integer> current = new HashSet<>();
    current.add(INITIAL_STATE);

    for (int i = 0; i < input.length; i++) {
        int idx = symbolIndex(input[i]);
        if (idx == -1) return false;
        Set<Integer> next = new HashSet<>();
        for (int state : current) {
            for (int ns : TRANSITIONS[state][idx]) {
                next.add(ns);
            }
        }
        current = next;
        if (current.isEmpty()) return false;
    }

    for (int state : current) {
        if (ACCEPTING[state]) return true;
    }
    return false;
}
```

## 10. Приложение. Инструкция по сборке и запуску

### 10.1. Требования

- JDK 17 или выше (проверено на JDK 25 Temurin);
- Maven 3.9 или выше.

### 10.2. Сборка

Из корня проекта:

```bash
mvn clean package
```

В папке `target/` появится `finite-automata-lab-1.0.jar`.

### 10.3. Запуск

**ДКА:**
```bash
java -cp target/finite-automata-lab-1.0.jar com.example.DfaVariant15
```

**НКА:**
```bash
java -cp target/finite-automata-lab-1.0.jar com.example.NfaVariant15
```

### 10.4. Запуск в IntelliJ IDEA

1. Открыть `DfaVariant15.java` или `NfaVariant15.java`.
2. Нажать зеленую стрелку рядом с `public static void main`.
3. Ввести тестовые строки в консоль, для выхода набрать `exit`.

### 10.5. Файлы JFLAP

- `jflap/dfa_variant15.jff` - ДКА в формате JFLAP;
- `jflap/nfa_variant15.jff` - НКА в формате JFLAP.

Открываются через File → Open в JFLAP.
